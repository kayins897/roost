# ZD-03 状态与成果模型短决策包（B2 / PD-01～03）

> 状态：REVIEW v2（按夜间任务书 N9 修订五处已知问题；方案待所有者选择，未授权实施）· Zcode（GLM）· 2026-10-25 夜
> 依据：PRD PRD-G-03/06、DECISION_BACKLOG PD-01~03、ADR-001/002/003 与现行代码事实（0.4.23）。本文只做决策材料，不改代码。

## 1. 两个主方案

| | 方案 A：六态保留 + 交互增强 | 方案 B：活动/计划 与 成果事实 分离（渐进） |
| --- | --- | --- |
| 模型 | `gamePlayState` 六态不变；"曾通关/全成就"靠状态+体验记录+个人评级间接表达；增强=详情页提示、更多手动体验记录 | 六态继续作为「当前活动/计划」维度；新增**可选**成果字段（通关事实、全成就标记；周目计数后置）独立表达"发生过什么" |
| 已通关仍玩 | 只能 ongoing，评级箔面消失（现状缺陷无法表达） | state=ongoing + completionFact=通关，箔面与评级保留 |
| 全成就 | 无表达位 | achievementFact 独立布尔，与通关互不推定 |
| 数据 | 零变更 | schemaVersion 仍为 1，走 0.4.16+ 新增可选字段同款路径（playPriority 先例）；不迁移、不重写旧库 |
| 旧版写入风险 | 无 | **已知边界（修订）**：现行代码的编辑保存保留未知字段（verify-workspace 的 futureItem 断言）——这只证明**当前与近版**行为，不证明所有旧版写入都安全。支持矩阵：0.4.16+（可选字段先例与保留断言在案的版本）为已验证；更早版本未逐一回测，存在丢新字段风险。回退与共存方案：升级前导出备份 + previous/daily 链可完整恢复；若需与旧版长期双写共存，需另行冻结测试矩阵（研发任务），不以"发布说明提示"替代验证 |
| 实现成本 | 小（纯 UI 提示） | 中（字段+两处 UI：详情成果区、编辑表单；右键不动） |

**推荐：方案 B，分两期落地。** 理由：PD-01 的四个评审场景中两个（已通关仍玩、全成就）在 A 下永久无法表达，且越晚分离、历史沉淀的"状态顶替事实"越多；B 的数据风险经可选字段路径验证可控（既有 futureItem/preserve 专项断言护航）。B-1（本期可实施）：通关事实 + 全成就两个可选字段与详情/表单编辑；B-2（后置）：周目计数、胜利次数 UI 与来源核验。

## 2. 必须固化的语义边界（两方案通用，实施时写入 ADR）

1. 暂时搁置与待体验同属「计划」视图（现状 plan=want+paused，搁置排后），不合并状态。
2. 持续游玩 ≠ 曾通关；ongoing 不自动清除或授予任何成果字段。
3. 待体验优先级与通关个人评级是两个独立维度（现状已分离，保持）。
4. 全成就与通关互不推定：可只全成就（无通关概念游戏）、可通关无全成就。
5. 已放弃不自动删除任何记录、评级或成果字段。
6. 未知 ≠ 否：周目/成就未记录时显示「未记录」，禁止按 0 或按记录数推算（周目 ≠ completed 记录数 − 1，不由日志计数反推）。

## 2.5 方案 B 的字段语义候选规则（供研发论证，未授权实施）

现有六态已含 `cleared`，B 再引入通关事实会形成**双重依据**，必须先定优先规则，禁止启动时自动补写：

- **旧 cleared 记录**：保留 `gamePlayState: cleared` 原值；通关事实字段初始为「未记录」（不自动回填），由用户手动确认或显式批量操作补记——不批量推断历史。
- **状态与事实冲突**（如 state=want 但通关事实=是）：两个字段各自如实展示，UI 标注「状态与成果记录不一致，可整理」；不自动改任何一方。
- **四值区分**：通关事实 = 未记录（未知）/ 是 / 否（明确未通关）/ 不适用（无通关点：MMO、纯竞技等）；未知显示「未记录」，绝不显示为「否」。全成就复选框同样需三态：未记录（空）/ 是 / 否（明确未全成就）——用「未确认 ≠ 未取得」的空态设计，而不是二值复选框。
- **改 ongoing 的交互**：从 cleared 改 ongoing 时通关事实保留不动；从其他状态改 ongoing 不授予事实。
- **旧版写入冲突**：旧版编辑保存含新字段的作品时按其版本行为处理（见上表修订）；新版读取旧库不迁移不规范化。

## 4. 概念定义（实施时进 PRD）

- **通关事实**：用户断言"取得过通关成果"，可带月/日精度日期或留空；与当前状态解耦。
- **周目**：从开始到达成通关事实的完整循环次数；仅用户手动增改或将来按明确规则导入，永不从日志推算。
- **单次胜利**：无通关概念游戏（肉鸽/竞技）的一局胜利记录；属体验记录扩展（B-2），不与周目混算。
- **完成日志**：体验记录 kind=completed 的普通历史条目；保留现状语义（其分钟数不并入累计时长）。
- **全成就**：用户断言取得全部成就；独立布尔，与通关事实、个人评级互不推定。

## 5. 自动记录日期（仅讨论，不实现）

若引入"状态切换→生成体验记录"快捷路径，仅限：**切换时弹出确认**（预填当月 YYYY-MM，可改可空可取消）；一条状态变更至多一条记录、重复切换同状态不重复生成；生成后即普通记录可删可改；不后台静默写入、不把录入日期当体验日期、不自动补历史。默认关闭亦可（纯手动补录保持现状）。

**修订补充**：成果事实自身的日期允许「未知」（未记录），但**体验日志的日期仍不可为空**（现有校验 isExperienceDate 要求 YYYY-MM 或 YYYY-MM-DD）——两者是不同字段不同规则，不因成果日期可空而放开日志校验；自动日志整体后置，任何实现不得生成虚假的"当日"历史。

## 6.5 评级与箔面资格随完成语义的变化（修订：现状评级在卡片仍能显示）

澄清现状：ongoing/搁置作品的**个人评级字段保留且卡片徽标仍显示**（MediaCard 的评级展示不筛状态）；缺的是：① 详情页编辑入口（GameRating 仅 want/cleared 显示输入）② 评级箔面（coverFinishFor 要求 state=cleared）。若选方案 B，三种候选资格规则供选择：

| 规则 | 评级可编辑 | 评级箔面 | 分档视图 |
| --- | --- | --- | --- |
| R1（最保守） | 仅 state=cleared（现状） | 仅 state=cleared（现状） | 仅 cleared |
| R2（推荐） | state=cleared 或 通关事实=是 | 通关事实=是（含 ongoing 仍玩） | 通关事实=是 |
| R3（最宽） | 任何状态可评（当作主观印象） | 通关事实=是 | 通关事实=是 或 否 |

R2 的含义：已通关仍玩（ongoing+事实=是）可编辑评级、箔面保留；无通关点游戏按「不适用」走 R3 行还是不评级，归入下一节提问。
