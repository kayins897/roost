# ZD-03 状态与成果模型短决策包（B2 / PD-01～03）

> 状态：REVIEW（方案待所有者选择，未授权实施）· Zcode（GLM）· 2026-10-25
> 依据：PRD PRD-G-03/06、DECISION_BACKLOG PD-01~03、ADR-001/002/003 与现行代码事实（0.4.23）。本文只做决策材料，不改代码。

## 1. 两个主方案

| | 方案 A：六态保留 + 交互增强 | 方案 B：活动/计划 与 成果事实 分离（渐进） |
| --- | --- | --- |
| 模型 | `gamePlayState` 六态不变；"曾通关/全成就"靠状态+体验记录+个人评级间接表达；增强=详情页提示、更多手动体验记录 | 六态继续作为「当前活动/计划」维度；新增**可选**成果字段（通关事实、全成就标记；周目计数后置）独立表达"发生过什么" |
| 已通关仍玩 | 只能 ongoing，评级箔面消失（现状缺陷无法表达） | state=ongoing + completionFact=通关，箔面与评级保留 |
| 全成就 | 无表达位 | achievementFact 独立布尔，与通关互不推定 |
| 数据 | 零变更 | schemaVersion 仍为 1，走 0.4.16+ 新增可选字段同款路径（playPriority 先例）；不迁移、不重写旧库 |
| 旧版写入风险 | 无 | 现行各版编辑保存保留未知字段（verify-workspace futureItem 断言）；仅早于未知字段保留机制上线的远古版有丢失风险，发布说明提示即可 |
| 实现成本 | 小（纯 UI 提示） | 中（字段+两处 UI：详情成果区、编辑表单；右键不动） |

**推荐：方案 B，分两期落地。** 理由：PD-01 的四个评审场景中两个（已通关仍玩、全成就）在 A 下永久无法表达，且越晚分离、历史沉淀的"状态顶替事实"越多；B 的数据风险经可选字段路径验证可控（既有 futureItem/preserve 专项断言护航）。B-1（本期可实施）：通关事实 + 全成就两个可选字段与详情/表单编辑；B-2（后置）：周目计数、胜利次数 UI 与来源核验。

## 2. 必须固化的语义边界（两方案通用，实施时写入 ADR）

1. 暂时搁置与待体验同属「计划」视图（现状 plan=want+paused，搁置排后），不合并状态。
2. 持续游玩 ≠ 曾通关；ongoing 不自动清除或授予任何成果字段。
3. 待体验优先级与通关个人评级是两个独立维度（现状已分离，保持）。
4. 全成就与通关互不推定：可只全成就（无通关概念游戏）、可通关无全成就。
5. 已放弃不自动删除任何记录、评级或成果字段。
6. 未知 ≠ 否：周目/成就未记录时显示「未记录」，禁止按 0 或按记录数推算（周目 ≠ completed 记录数 − 1，不由日志计数反推）。

## 4. 概念定义（实施时进 PRD）

- **通关事实**：用户断言"取得过通关成果"，可带月/日精度日期或留空；与当前状态解耦。
- **周目**：从开始到达成通关事实的完整循环次数；仅用户手动增改或将来按明确规则导入，永不从日志推算。
- **单次胜利**：无通关概念游戏（肉鸽/竞技）的一局胜利记录；属体验记录扩展（B-2），不与周目混算。
- **完成日志**：体验记录 kind=completed 的普通历史条目；保留现状语义（其分钟数不并入累计时长）。
- **全成就**：用户断言取得全部成就；独立布尔，与通关事实、个人评级互不推定。

## 5. 自动记录日期（仅讨论，不实现）

若引入"状态切换→生成体验记录"快捷路径，仅限：**切换时弹出确认**（预填当月 YYYY-MM，可改可空可取消）；一条状态变更至多一条记录、重复切换同状态不重复生成；生成后即普通记录可删可改；不后台静默写入、不把录入日期当体验日期、不自动补历史。默认关闭亦可（纯手动补录保持现状）。

## 6. 线框差异（右键 / 详情，仅示意）

现状右键（ZD-01 后）：`游玩状态 [六态] → 通关评级 [SSS..C/未设置]`（仅 want/cleared 出等级行）
方案 B 详情新增独立区：`通关成果 ─ ○未记录 ◯通关(2024-05) ◯不适用　☐ 全成就`（与"游玩状态""个人评级"三区并列；右键菜单不承载成果编辑，避免菜单过载）
