# 0.4.34 电影与剧集消费逻辑

## 范围与基线

所有者明确要求电影／番剧／连续剧作为一级菜单，按消费逻辑设置二级分类，主题片单只保留电影。本轮基线`4ea7146`（0.4.33候选），独立分支`codex/screen-consumption-v0434`。不合main、不推送、不发布，不改其他媒体模型。

## 当前规则

- 电影：想看／看过；番剧、连续剧：想看／在看／看过。各类另外提供全部汇总视图，二级计数仅统计当前类型。
- 想看是下一次观看计划，看过是历史事实。已看过的电影安排多刷可同时出现在这两类；重看的剧集可同时出现在在看与看过。计数不能相加作为作品总数。
- 普通日志、片长与季集指针不代表完整看过。沿用0.4.33独立轮次、日志和季集进度，不自动关联同IP的不同季、不自动按最后一集生成看过历史。
- 电影片单仅电影页展示和分配。修改旧混合片单只调整当前活跃电影，历史剧集、隐藏、回收、失联ID和扩展字段保留；删除片单仍不删除作品。
- 切换一级类型退出多选，清理局部标签、资料筛选、片单和右键菜单；网格／列表沿用当前选择。跨板块返回保留会话内类型。
- 详情、右键、完整编辑器及多选均按类型给出相同分类入口。新增和TXT清单继承当前类型；JSON中的明确类型保留，不强行改为当前类型。混合JSON统一选在看时，电影保持想看，界面明示适用范围。

## 数据兼容与回退

无新字段、存储键或schema变更，仍为schemaVersion1。旧`watching/idle/abandoned`及旧status不删除、不启动改写：电影无看过事实时归入想看，有事实时可从看过找回；剧集旧搁置、弃看同样只读归类。未知旧子分类暂在电影中可访问，作品资料显示原值，可手动纠正类型。

只修改导演等资料不会把旧状态改写为派生显示值。显式更改分类仍走既有快照／修订检查／备份保存链。正常启动前仍建议导出完整备份；回退0.4.33可直接读取本轮格式，旧版会再次展示旧分类入口。原始dirty的`qiyu-desktop`不改动；测试只使用隔离合成库。

## 实施与验证入口

- `src/domain/screenConsumption.ts`：类型、菜单、只读分类规则；对应单测覆盖旧状态、未知类型、多刷及季集分离。
- `features/screen/`：一级导航、二级筛选、电影片单、详情及右键；`screenEditor.ts`／`WorkEditor.tsx`／`SteamLibraryImport.tsx`统一录入语义，`App.tsx`仅接线。
- `scripts/verify-screens.cjs`：实际Electron专项，用临时目录写入合成库，覆盖菜单、无迁移、进度、多刷、修订冲突、导入、批量、片单保护、响应式及进程重启。
- 非作者只读审查已完成，未发现阻塞问题；浏览器导航8项通过。最终源码／成品检查结果以随交付验收报告为准，不复用0.4.33旧结果。

## 限制与接力

同IP分季关联、整套剧集元数据导入、追番更新提醒、豆瓣账号同步和日历接入均未新增。原有单件豆瓣抓取本轮未真实联网回测。详情点标签仍与局部菜单筛选交集，跨类型的特殊入口可能需先切类型／全部，此为既有交互边界。

接手先核对分支和git log，运行npm test、npm run desktop:build及影视专项；打包仅免安装ZIP，不覆盖旧交付。回退本轮提交即可恢复0.4.33行为，无需逆迁移。
