## 问题与补正要求

### R1 · P3：重复 ratingOrder 的注释与实际兜底规则不一致

位置：`src/domain/gamePlanning.ts:31–41`，特别是第 39 行。

函数注释写着：两个有效顺序值相等时保留调用者的稳定顺序。但本次新增的真实评分降序也作用于这种情况。合成输入 `[8.2/ratingOrder=0, 8.9/ratingOrder=0]` 的输出变成 `[8.9, 8.2]`，读取本身不写库。

旧版本按精确小数分别保存 `0..n`，合并评分段后出现相同有效顺序号是正常兼容场景。任务书要求确定、稳定的兜底，未规定必须保留输入索引；现行“有效顺序号优先，同号按真实评分降序，再按输入索引”的规则本身符合该要求。应修正注释并在交接中记录该规则，可补评分维度的重复序号用例固定行为。当前重复序号用例主要覆盖 `priorityOrder`。

证据：独立审查目录 `evidence/codex-review-v0430/duplicate-rating-order.json`。初审曾误将“稳定兜底”理解为必须保留输入索引；复核调用链与任务书后撤回该功能缺陷定性。本条只保留注释与说明的纠正，不要求更换已验证的排序规则。

### R2 · P2：RuiC 尚不是可公平比较的平面封面预览交付

1. `design/ruic-card-preview/README.md:45` 明确说明，上排现有多彩/镭射仅为静态 CSS，不含正式 WebGL、指针光位与倾斜；下排是完整 Three.js 查看器，自动轻转，尺寸和构图也不同。这不能支撑“与现有正式效果等条件比较”的验收。
2. `tools/make_layers.py:132–155` 先生成背景、主体、文字，最后再合成为封面。三例是合成分层演示，不能代替任务要求的三张普通平面封面材质适配。分层来源有诚实说明，应保留该说明并补齐平面样本。
3. 唯一入口为手动运行 Node 命令（预览 README 第 9 行）；交付目录没有可直接启动的交互预览。正式包不集成预览是正确的隔离边界，但需要另行交付免配置的独立预览入口。
4. 上游 `flake` 稀疏高光仍在 `vendor/app.bundle.js:31185–31186` 中叠加，未按任务适配要求关闭；只有单帧截图，缺少固定角度连续帧或短录屏。

补正：保留已跑通的上游管线；加入平面封面路径；四种效果用同一素材、卡面尺寸、角度和指针输入比较，现有两档必须使用正式渲染路径；关闭适配版稀疏闪点；提供独立启动器与三例连续画面。不要因此替换生产渲染器或要求所有者安装 Blender。

独立浏览器检查确认：三例均实际创建 WebGLRenderer，资源全部来自本地，无页面错误或 4xx；390 宽无横向溢出。上游缓存提交与声明的 `712fc9f29e6e6492b8e84791396a42003f4f0261` 一致，三份卡片 MIT 许可证存在。截图中的同心线来自合成原图，不应误称为新增网格。没有独立复跑 Blender 重建，也没有对完整查看器所有控件作验收。
