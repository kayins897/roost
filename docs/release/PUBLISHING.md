# 免安装预发行流程

普通开发、分支推送和 PR 不会发布。主分支合并与推送版本标签必须先得到所有者明确授权；本流程不授予任何 Agent 自动发布权限。

1. 在独立分支完成修改与非作者审查，更新 package.json／锁文件、CHANGELOG、README、`验收步骤-<版本>.md` 和 `RELEASE-v<版本>.md`。
2. 运行当前专项、核对隐私及来源记录，建立 PR。仅在已授权后合并主分支，核对远端 main 的版本及提交。
3. 给已合入 main 的提交创建并推送 `v<版本>` 标签。`.github/workflows/prerelease.yml` 校验标签等于 package 版本、提交已在 main、验收及发布说明齐全。
4. Windows 构建任务运行单测、生成免安装 ZIP、核对包内文件和成品批量收录。测试使用隔离目录与合成数据；日志随 Actions artifact 留存 7 天。
5. 发布任务只下载构建产物并检查 SHA-256；独立的 `contents: write` 权限仅用于创建预发行版，上传 ZIP 与校验文件，不生成安装器或改成稳定版。
6. 核对 Actions 结论、Release 的预发行标志、标签提交、附件字节数及散列。下载附件核验 `SOURCE.json` 并按验收步骤体验。托管构建包与本地先前构建包分别记录，不混用校验值或声称相同字节。

失败时保留日志，修复后走新的审查提交与明确授权流程；不强推、移动已发布标签，不覆盖已有发行附件。发布创建失败时先核对是否已有同名 Release，不能盲目重跑或覆盖。

`Validate QIYU` 仍为手动 CI，验证主线专项；旧 `npm run test:workflow` 保留作历史套件入口，部分旧卡面／分类断言待适配，不是当前发布门禁。首次托管运行前只能声称本机验证通过，不能预先声称 Actions 成功。
