# 全局日历首页与阅读热力表

> 2026-10-27｜所有者确认方向：日历恢复为全局首页，展示跨媒体的体验记录及未来计划；书籍页按每日阅读时长着色。尚未实现；具体布局、数据及兼容设计待审阅。任务见 [CALENDAR_PHASE1](../tasks/CALENDAR_PHASE1.md)。

## 1. 已确认范围

| ID | 规则 | 验收方向 |
| --- | --- | --- |
| CAL-R01 | 日历是之前移除的首页的新用途，覆盖游戏、书籍、影视等媒体；不只属于书籍页 | 首页可回顾何时通关游戏、看过哪些影视、读了哪些书；不增加第五种媒体类型 |
| CAL-R02 | 同时容纳实际经历和未来计划，二者清楚区分 | 某日可有已发生记录与未来安排；时间过去不自动把计划变为完成 |
| CAL-R03 | 书籍页另有类似 GitHub 的阅读热力表，按每天实际阅读时长显示深浅 | 当天多书可汇总，点击日期可看书目及时长；计划不产生阅读热度 |

书籍的计划/阅读记录仍在同一书籍库一次展示一面；全局首页的日历不替代该切换，也不把所有书籍内容集中搬走。记录和计划的具体编辑布局还未验收。

## 2. 建议原型（待审阅，不视为已定布局）

- 日历首页：月份导航、回到今天、媒体筛选、月历以及选中日期的清单。用作品封面缩略图和简短事件文字表现经历；未来安排采用明确的“计划”文字/样式，不仅靠颜色区分。
- 点击某日，可查看当天记录、打开作品详情、补录实际经历或安排计划。无具体日期的计划继续保留在对应媒体计划中，不要求为了进入日历硬填日期。
- 年度阅读热力表放在书籍页，颜色随分钟数递增；悬停、聚焦或点击均可查看日期、已记录分钟及书目。窄窗提供可滚动或切换的月份范围，不压成无法操作的细点。
- 第一版建议允许手动录入每天的阅读分钟数，不依赖后台计时或电纸书连接。起止时间计时器、连续打卡、目标提醒和成就奖励不属本轮已确认范围。
- 具体分钟档位、颜色和首页默认打开行为由原型评审确定，不把游戏评级或计划优先级复用为热力表强度。

## 3. 日期与统计保护要求

以下由既有“真实记录、个人内容保护”原则推导，是实现与验收必须覆盖的边界；具体存储方案仍待 PD-13：

1. **事件日期与录入日期分开。** 通关分类、作品收录时间、最近修改时间和累计时长都不能代替“某天通关”。当前状态也不能证明某天看完电影或读完书。
2. **保留日期精度。** 只有月份/年份的旧记录归入相应范围的历史清单，不能硬塞到某月第一天；日期未知仍可保存，不计入日格或热力表。
3. **分钟、零和未知区分。** 热力表强度只用明确的日级阅读分钟。没有记录显示“未记录”，不能声称没有阅读；明确 0 分钟不产生正热度；有阅读事实但无分钟的记录可在当天清单显示“时长未记录”。
4. **同一事实只计一次。** 日历、书籍详情和热力表读取同一已确认记录。来源重导、手工记录与来源重叠、总计与明细混合需在预览中识别，不能简单相加；同日经去重确认的独立阅读记录可累加，包含同书多次和不同书籍，日总计与其明细不能重复相加。
5. **累计不是每天。** 来源只给总阅读时长、进度或最后阅读时间时，不均摊、不按进度推算，也不把全部分钟放到最后一天。BOOK-02 必须单独核对日级数据是否可取。
6. **计划不等于经历。** 计划日期过去仍是未执行计划，不自动染亮热力表或生成完成事件；移动/取消计划不改已发生记录。
7. **跨日和时区需明确。** 时间戳按已确认的本地日归属策略展示，来源已给出的日历日期不被 UTC 转换平移。跨午夜的区间有证据才拆分；只有某日和总分钟的记录不推测开始时间。
8. **修改可以校正。** 补录、改日期、改分钟与删除事件应同步更新两种视图；保存失败保留草稿。仅移除日历记录不默认删除作品，反向的回收/永久删除及旧备份恢复规则需另行明确。
9. **不混用完成含义。** 游戏已有明确完成事件可以展示，普通体验日志不自动变为通关次数；电影的一次观看和剧集进度不自动当作整部剧看完。此处不重新定义媒体业务分类。

## 4. 实际代码基线与待决定项

基于 `9577012125c76bbfc219fda4be0b1a6f75cb7da4`（package 0.4.30）核查：

- 通用 `ExperienceEntry` 已有月/日日期、种类、笔记与可选分钟，且明确不覆盖累计游玩时长；`src/domain/catalog.ts` 的 `timelineEntries()` 可汇集作品日志。`src/presentation/RecordEditors.tsx` 已能录入实际日期和本次分钟，可复用；现有日志不是完整日历/阅读时间模型。
- 游戏另有 `completionEvents`，其实际发生日期可未知或保持年/月/日精度，`recordedAt` 是录入时间；不能与普通 `completed` 日志盲目合并或双计。
- 当前导航只有四媒体且默认游戏，没有首页入口。残留月份活动格/时间线样式，但本库可达 Git 历史未找回可直接恢复的首页日历组件；不能据此否定所有者提到的旧首页曾存在，也不能宣称直接启用即可恢复。
- 日级阅读来源、未来日程模型、日历页面及阅读热力表尚无完整实现。累计游玩时长及 Steam 同步数据不提供每天的游玩轨迹。
