# 书籍模块需求基线

> 2026-10-27｜所有者已确认产品方向；功能尚未实现。具体任务见 [实施与接力](../tasks/BOOKS_PHASE1.md)。本文件是书籍规则正文，不取代其他媒体的规则。

## 1. 目标与使用场景

阅读记录与未来阅读规划同样重要。主要任务是知道自己读过哪些书、留下读后感，并安排接下来读什么。覆盖专业书籍、文学及网络小说；阅读渠道包括电纸书和纸质书。摘抄是辅助能力，不作为首期重点。

界面和记录不依赖电纸书在线或账号持续授权。微信读书和豆瓣是首批资料/个人记录来源，不强制使用付费 AI。

## 2. 已确认的产品规则

| ID | 规则 | 验收场景 |
| --- | --- | --- |
| BOOK-R01 | 同一个书籍库以“阅读计划／阅读记录”切换，一次只展示一面；不是两个并列展示的主页面，也不提供同时选中显示全部的组合 | 切换后保留同一书籍模块，当前只出现所选面的内容 |
| BOOK-R02 | 在读作品在计划中置顶 | 在读与尚未开始的计划混合时，在读先展示；同组顺序策略另见待决定项 |
| BOOK-R03 | 一本书可同时拥有过去的阅读记录与未来重读计划；不复制书目，不用计划覆盖历史 | 已读某书后加入重读计划，两面分别展示对应内容；上一次读后感保留 |
| BOOK-R04 | 计划承载想读原因与先后顺序，支持加入计划、开始阅读、调整顺序 | 重排不改书籍客观资料、历史记录及感想；优先级名称和枚举未决定 |
| BOOK-R05 | 阅读记录以自己的感想为重，区分一句话印象与长篇读后感；多次阅读可留下不同感想 | 重读后新增感想不覆盖前一次；长文可展开，库卡片能呈现一句话印象 |
| BOOK-R06 | 允许补录历史日期或月份，也允许日期未知；不以收录或导入时间冒充阅读时间 | 不记得何时读完仍可登记读过；导入缺日期不自动填今天 |
| BOOK-R07 | 进度、摘抄及评分为可选信息，不成为登记已读或加入计划的门槛 | 没有页码、章节、摘抄或评分，也能完成核心流程 |
| BOOK-R08 | 导入先预览、匹配与选择内容，再确认保存；重复导入不重复收录 | 同一来源书目或个人记录重复导入，仍只有相应的一条记录 |
| BOOK-R09 | 不仅凭同名强制合并；不同译本/版本需确认，同一条书目可关联多个确切来源 | 两个来源的不同版本先列为待确认，不能把不同页码和书评误并为一个版本 |
| BOOK-R10 | 导入已有个人评价时保留来源；两平台个人书评可同时保留 | 个人书评不被当成站点公众评论，导入不覆盖另一来源的个人内容 |
| BOOK-R11 | 来源刷新不静默覆盖栖域已修改的评分、封面和感想；冲突在预览中明确呈现 | 读取失败、取消或同值操作不写库；保存失败不显示成功且保留待确认内容 |
| BOOK-R12 | 保留来源评分的原始刻度及未评分语义，不擅自转为游戏评分或优先级 | 未评分不会变成 0；来源评分换算方案未批准前不写入统一分数 |
| BOOK-R13 | 书籍页提供类似 GitHub 的阅读热力表，以每日阅读时长决定颜色深浅，帮助培养阅读习惯 | 同一天读多本书可汇总分钟数；缺少日期或日级时长时不伪造热度；计划不计入已读时长 |
| BOOK-R14 | 全局日历是首页，阅读活动可在日历回顾，未来阅读计划也可纳入；不是仅在书籍页增加日历 | 同一条有日期的阅读时长记录同时用于日历与热力表，不要求重复填写；其他媒体的记录由全局日历展示 |

上述是已确认的用户行为与保护要求，不代表新增字段、存储键、迁移或完整页面已经获准按某个技术方案落地。具体结构仍须先完成兼容设计。

## 3. 首批导入内容

### 书籍基础资料

- 核心：封面、作者、译者、出版社、简介。
- 补充：书名/原名、出版时间、ISBN、来源链接与编号。
- 缺失字段保持未记录，不推测填充。作者与译者应区分；简介与个人读后感应区分。
- 既有豆瓣单书 URL 读取及预览复用，不能称为已经支持完整书架或个人评分导入。

### 个人阅读数据

- 目标：平台能明确提供的在读/读完、进度、实际日期、自己的评分和书评。
- 平台书架中的一本书不自动等于读过或明确想读；不确定的归类先让用户确认。
- 来源中的阅读进度不根据笔记数量推算；未知不等于零。日期精度按来源保留。
- 公开热门短评、他人长书评和站点总评分不是本轮“个人评价导入”的替代品。
- 暂不把单个来源的书架结果称为完整终生阅读历史；已移出书架的书是否可枚举需验证。
- 热力表需要日级阅读时长。来源若只给累计时长或最后阅读时间，不能均摊到每天，也不能把全部时长算到最后一天；无法取得明细时保留手工补录入口。是否有可用的日级来源另做实测。

2026-10-27 核对官方文档；未登录用户账号、未调用个人 API、未验证栖域直连。

| 来源 | 已核实的事实 | 尚未完成 |
| --- | --- | --- |
| 豆瓣 | 当前栖域代码有图书 subject URL 解析、基础资料候选、补空缺及去重；公开图书页面包含作者、译者、出版社、简介等内容 | 当前解析/候选不完整携带全部新字段；个人评分/书评不是现有能力；账号数据读取方式及实测待做 |
| 微信读书 | 腾讯官方 Agent Skills 文档提供个人 Key 路径；book/info 列出基础资料；shelf/sync、book/getprogress 列出书架与进度；review/list/mine 列出自己的想法/点评等内容 | Agent 路径不直接等于通用第三方桌面授权；栖域接入适用范围、字段完整度、分页、取消、失效与真实返回未验证 |

## 5. 实际代码基线

核查生产源码基于 v0.4.30 后续补丁 `9577012`。当前书籍使用共享 MediaItem 与通用四态，已有基础资料、标签、一句话印象、长文和通用体验日志。书籍详情仍是通用详情，不是新的书籍专属 Bento。

当前没有独立的计划/阅读轮次、结构化页码/章节，以及明确的译者、出版社、ISBN、简介字段。MetadataProvider 仅有 steam/douban；新的微信读书来源不能只追加一个字符串就声称兼容。现有同名批量去重也不能直接承担版本合并。

旧字段保留及导入扩展须一起审查：作品校验、候选 DTO、共享 IPC、批量导入白名单、去重、排除清单、完整备份和旧版回退。schemaVersion 相同不代表旧程序可安全写新数据。

## 6. 待决定的实现细则

以下进入 [PD-12](DECISION_BACKLOG.md)，不由 Agent 擅自确定：

1. 计划、当前阅读及多次阅读记录的字段/关系，旧四态和通用日志如何兼容；不确定的历史只读保留。
2. 作品、版本与阅读轮次的最小关系；如何关联来源而避免同名不同译本误并。
3. 计划排序/优先级是否分档及名称；在读组内顺序；两面具体布局与默认选择。
4. 各平台评分原值与栖域统一评分的关系、换算与冲突选择；不自动改为字母或 0–10。
5. 新字段/来源值的校验、备份、旧版兼容和回退；未批准不可逆迁移。
6. 日级阅读时长的来源、去重、跨日归属与记录模型；热力表具体色阶和日历编辑方式见 [全局日历](CALENDAR.md) 及 PD-13。已确认按时长着色，不再将记录次数或页数作为默认强度。

## 7. 视觉和实施边界

延用现有深色设计、封面浏览及卡片语言。读后感与阅读经历是详情重点，资料与标签分开；具体书籍原型尚未验收，不按游戏卡片逐项照搬。

书籍任务不扩展影视/音乐的专属分类，不重构游戏分类或卡面，不将立体封面实验接入书籍，不增加付费 AI、复杂计时或设备同步依赖。另立全局日历任务可复用各媒体明确的体验记录，这不等于授权重构各媒体。摘抄和汉王适配后置。首次来源验证以只读方式开展，不代用户在平台发表、修改或删除内容。
