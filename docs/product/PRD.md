# 产品需求基线

> 版本：1.0｜2026-10-25｜状态：正式需求基线，含显式未决项。
>
> 来源：所有者既有需求及已确认的基线审阅。这里只定义规则和验收方向；具体开发须有批准任务。状态拆分、全成就、自动事件、标签 OR、智能视图持久化、刷新覆盖及正式 UI 大改均未因此获得实现授权。

## 阅读约定

- **已确认方向**表示产品约束；**现有**表示当前代码行为，不能因此认定所有场景均验收通过；**待决定**表示不得直接修改的候选语义。
- 决策状态与实现证据分别记录；源码、自动化与人工验收证据见[能力基线](CAPABILITY_BASELINE.md)。未决项以[决策清单](DECISION_BACKLOG.md)编号追踪。
- 一级模块、设备顺序、协作职责和非目标见[项目章程](PROJECT_CHARTER.md)，不在此重复。

| ID | 任务 | 成功结果 | 优先级 |
| --- | --- | --- | --- |
| JT-01 | 发现感兴趣的游戏，先存下来 | 少量输入即可收录，资料和评价允许以后补 | P0 |

## 统一作品与资料规则

| ID | 规则与现状 | 验收原则 |
| --- | --- | --- |
| PRD-COM-01 | **已确认/现有**：作品主记录关联多个平台和来源编号；同名不强合并 | 跨平台信息可在一条作品上维护，个人记录无需复制；编号冲突进入确认而非猜测 |
| PRD-COM-02 | **已确认**：低负担收录；在线识别先预览，失败保留手工入口 | 不要求付费 AI 或立即写评价；最小手工收录的必填项以表单校验及对应任务验收为准 |
| PRD-COM-03 | **已确认/现有**：来源补空缺、合并平台/编号，不静默改个人字段或已有封面 | 人工名称、封面和私人内容保持；Steam 时长只在用户选择补增时采用明确且更大的值，既有更大值保留 |
| PRD-COM-04 | **已确认/现有**：隐藏、回收和永久删除不同，且独立于体验状态 | 隐藏可恢复；回收保留完整记录；永久删除须按现有回收站确认路径，不因“放弃”自动删除；已有编号排除避免再次导入 |

当前客观字段包括名称/原名、创作者、年份、平台、封面和来源编号；私人字段包括状态、时长、等级、标签、短印象、长测评、喜欢与体验历史。“简介”“来源评分”、字段来源追踪、人工锁定和自动刷新是候选扩展，不是当前能力。新的覆盖政策先完成 PD-08，不因增加来源而先迁移存储。

## 游戏规则

| ID | 基线规则与边界 | 验收重点 / 决策依赖 |
| --- | --- | --- |
| PRD-G-01 | **已确认/现有**：游戏平台是属性；一作品可拥有多平台 | 不凭相同标题或导入顺序建立错误关联 |
| PRD-G-02 | **已确认/现有**：时长优先显示，状态随后；未知和真实零区分，二者独立保存 | 不凭时长推断玩过、通关或评级；手工和同步值按明确操作写入 |
| PRD-G-03 | **现有**：待体验、游玩中、已通关、持续游玩、暂时搁置、已放弃六态；旧 `replaying` 兼容读取为持续游玩 | 保留旧值可读，启动不重写。独立完成事实、持续游玩与通关关系及全成就见 PD-01/02 |
| PRD-G-04 | **现有**：待体验优先级与通关个人评级各有 SSS/SS/S/A/B/C，独立字段和手动顺序；分档可折叠、同级可拖动 | 状态变化保留已有等级，不猜测默认等级。仅已通关可编辑个人评级及显示评级箔面；持续游玩新评级资格待 PD-01 |
| PRD-G-05 | **已确认/现有**：玩法、题材、游玩场景、其他四组，自定义标签用于查找 | 当前组内 AND、跨组 AND；同组 OR、转组、空标签目录另见 PD-04，决定前不改变已有结果 |
| PRD-G-06 | **现有**：手动开始/进展/完成/随记；日期可精确到月或日，本次分钟数不自动加总 | 不用收录日替代体验日，不以完成日志数减一算重玩。周目/胜利和自动事件见 PD-02/03 |
| PRD-G-07 | **已确认/现有**：一句话印象和长测评分开，允许为空 | 新印象单行且最多 80 个 Unicode 码点；旧长文无损保留，打开/折叠不拆写，保存失败保留草稿 |
| PRD-G-08 | **已确认改善方向、待设计**：右键内直接选优先级或评级，减少独立弹窗 | 当前仍会二次弹窗；先确认原型。只改善现有待体验/已通关入口可独立设计，搁置归属及持续游玩资格等 PD-01 决定后实施 |

待体验计划目前合并展示待体验与搁置，搁置置底。所有者最新草图希望进一步贴近这个规划关系，并使已通关仍持续玩的作品能保留完成成果与评价；草图尚不构成新状态枚举、字段或自动迁移方案。

游玩场景如“刚需联机”“需要沉浸”“放松解压”是可配置标签示例，不固化为不可编辑的枚举。封面边框反映状态，评级派生反光，不为悬浮或筛选写收藏。

## 书籍、影视与音乐

- **PRD-B-01 / B-02**：书籍包含专业书籍、严肃文学、网络小说等，保留现有豆瓣图书 URL 识别、预览与手动回退。关键词搜索先完成 PD-07；阅读页数/章节/重读等进度见 PD-06。
- **PRD-V-01 / V-02**：影视包含电影、番剧、连续剧，保留豆瓣影视 URL 导入。电影与追剧进度不应未经讨论直接套用游戏六态，专属字段/显示见 PD-06。
- **PRD-M-01**：音乐最低优先级，主粒度尚未确定，不提前建立歌曲/专辑/歌单全链路或强制播放能力。

当前非游戏仍使用通用四值进度，这是现状，不是最终产品语义。电影和音乐无需承担游戏式“通关/游玩中”措辞的既定要求。

## 跨模块与质量约束

| ID | 规则与验收 |
| --- | --- |
| PRD-X-01 | 当前板块搜索、排序和临时筛选已有；不要把顶部搜索误称为全局搜索。命名保存动态筛选为智能视图仍待 PD-05 |
| PRD-X-02 | 批量收录保留预览、去重和只新增；与整库恢复严格区分，恢复替换前保留原文 |
| PRD-X-03 | 批量编辑只修改选中范围与明确选择字段，失败不冒充成功；保留其他私人及未知字段 |
| PRD-UX-01 | 主观内容为重、资料渐进披露、内容优先于特效；状态有文字/图标，键盘焦点可见，减少动态和窄窗仍可操作 |
| PRD-UX-02 | 已确认主题/材质为当前基础；三套卡片/详情原型经所有者选择后再正式大改，不借竞品研究重置已有 UI |
| NFR-01 | 离线可查阅整理；网络超时、来源拒绝或资料缺失有可理解反馈和回退 |
| NFR-02 | 不在真实用户库上测试；沿用校验、修订冲突、原子保存、备份链和未知字段保护，数据/存储键变更先批准兼容及回退方案 |
| NFR-03 | 性能、无障碍、真实来源与成品分别验收；动画以 60Hz 为目标，不宣称未测设备都达标 |
| NFR-04 | 本地优先、分层、小步可审查；不因 Agent 切换频繁更换架构，不依赖付费 AI |

核心回归场景：合成数据中重复导入不复制个人记录；多平台且搁置游戏改标签后历史保留；给旧电影补录月份不冒充今天；豆瓣失败仍能手工收录；保存冲突/失败可恢复短长文和日期精度。组合条件中的“未通关”若指独立完成事实，须等 PD-01 后再验收，不能视为当前已有筛选。

新增需求或改规则时，将批准人、日期、范围和决定编号写入任务及 ADR/本文件；当前行为变化由对应任务验证，不用“已确认方向”替代实现与验收。
