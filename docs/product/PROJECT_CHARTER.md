> 版本：1.0｜2026-10-25｜状态：正式产品方向基线。
>
> 来源：所有者既有需求、2026-10-25 基线审阅及其确认。本次确认授权 B0/B1 基线整理，不自动批准文内列出的候选功能、数据变更或 UI 大改。

## 定位与核心价值

栖域是本地优先的个人文娱收藏与体验管理应用。它统一管理分散的作品，帮助用户便捷收录、查找、安排体验并留下自己的理解。

优先解决三个问题：

| 问题 | 产品应做到 | 避免增加的负担 |
| --- | --- | --- |
| 多平台收藏分散且容易重复 | 作品为主记录，平台与来源为属性；可靠编号优先判重 | 强制绑定全部平台、重复填写同一作品 |
| 收藏增加后难以选择下一部 | 状态、时长、标签和待体验优先级辅助选择 | 为整理而强制填写大量客观资料 |
| 个人体验难以回顾或被来源覆盖 | 主观内容与客观资料分开，历史真实、数据可备份 | 自动推测评级、通关或实际体验日期 |

## 范围与顺序

| 一级模块 | 已确认范围 | 当前优先级 |
| --- | --- | --- |
| 游戏 | Steam、Switch、PS5、TapTap、本地收藏等来源；跨平台作品、重复/持续游玩 | 最高 |
| 书籍 | 专业书籍、严肃文学、网络小说等；豆瓣链接收录 | 次于游戏 |
| 影视 | 电影、番剧、连续剧；豆瓣链接收录 | 次于游戏 |
| 音乐 | 基础收藏；歌曲、专辑或歌单等主粒度尚待决定 | 最低 |

第一阶段以项目所有者的 Windows 使用场景为验收出发点；类似习惯的其他个人用户是后续验证方向。Windows 优先，Android 与跨设备同步后置。当前不增加第五个一级板块，也不要求实现播放器、游戏平台替代品、社交服务或云服务。

## 不变的产品原则

1. **本地可用**：离线可以查阅和整理已有收藏；在线资料是增强能力。
2. **低收录成本**：先收录再完善，不依赖付费 AI API，不要求每件作品立即分类、评价。
3. **作品中心**：平台不作为一级内容分类；同名不等于同作品，不能用名称强行合并。
4. **个人内容优先**：状态、标签、优先级、评级、印象、测评和历史不被外部资料静默改写。Steam 时长仅按用户确认的补增规则处理。
5. **真实记录**：未知时长与零不同；拥有不等于玩过，收录时间不等于体验时间，游玩时长不推导完成事实。
6. **内容与易用优先**：封面和个人内容是视觉主体，特效不遮挡；状态同时有文字/图标提示，不能只靠颜色。
7. **可维护且可恢复**：清晰分层、稳定契约、小步变更；保护现有收藏、未知字段和备份。

Apple、Steam、PlayStation、明日方舟以及后续指定项目是设计参考。研究结论必须结合栖域任务评审，不能直接成为产品需求或架构迁移理由。

## 长期协作职责

| 角色 | 职责 |
| --- | --- |
| 项目所有者 | 决定产品方向、批准重大技术/数据/UI 决策、最终验收；明确合并及发布授权 |
| Codex | 长期技术与主要集成负责人；架构把关、核心开发、代码审查、正式版本集成 |
| DeepSeek Harness | 长期辅助开发者；可独立承担明确边界内的开发、测试、修复、研究、文档，Codex 不可用时继续已批准任务 |
| Zcode / GLM | 临时突击资源；适合独立模块、研究、原型和测试，有限时离场交接，不承担必须长期在线的责任 |
| ChatGPT | 产品讨论、设计审阅、技术方案评估及协作规范整理 |

全部 Agent 按任务风险接受相同审查要求，不用模型名称替代质量证据。多 Agent 使用独立分支/worktree，禁止未经审查合并；临时接手开发不自动获得合并或发布权限。Codex 额度不足触发交接，不能使已批准的独立工作停摆。细则由[流程入口](../process/README.md)和仓库工程规范统一维护。

## 如何衡量改进

先使用可重复的用户任务测量收录步骤、找回效率、错误恢复、个人内容安全与可理解性，再由所有者设定量化目标。不要虚构 KPI，也不要用单次动画帧率或生成代码成功替代完整验收。

功能规则与验收见 [PRD](PRD.md)，真实实现见[能力基线](CAPABILITY_BASELINE.md)，未决问题见[决策清单](DECISION_BACKLOG.md)。已接受技术决定继续记录于 [ADR](../DECISIONS.md)，不在本章程复制第二套架构规范。
