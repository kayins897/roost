# PD-12 / PD-13：书籍与日历的最小数据方案（待确认）

> 2026-10-27。结合所有者已确认产品方向与实际 0.4.30 源码提出；不是已接受 ADR，不授权正式字段、迁移或新来源写库。可操作原型只使用独立内存样本，其类型不是本方案的最终存储定义。

> 本轮补充确认：计划是年／月／周范围内的可选作品，允许季节、月份、月初中末及自然周；同作品细化保留身份，宽泛安排不强行落日，不自动顺延或变成经历。现有“可选目标日期”不足以完整表达，正式实施前须补充区间／不连续冬季窗口、细化关系及旧精确日期共存方案。预览的 `PlanPlacement` 只用于验证交互，不是已批准字段；见 [本轮交接](../tasks/CALENDAR_TIMELINE_PREVIEW.md)。

## 推荐的关系

保留一条 `MediaItem` 代表一个明确版本的书。同一译本可经用户确认关联豆瓣和微信读书；同名不同译本仅作为候选，不强行合并。首期不另建复杂的抽象作品/版本实体层。

建议在现有作品上增加三类可选关联，具体名称和校验待实施设计：

| 关系 | 最小内容与边界 |
| --- | --- |
| 计划 | 稳定身份、原因、顺序、可选目标日期、未开始/在读关系；允许过去读过的书继续有未来计划。目标日期过去不变成阅读事实 |
| 阅读轮次 | 稳定身份、可选实际开始/完成日期与精度、阅读关系；不记得日期仍能登记读过。不在这里重复保存日级分钟 |
| 个人评价 | 稳定身份，可选关联阅读轮次，一句话/长感想，来源个人记录身份及原始评分/刻度；无法确定属于哪轮就挂在书目，绝不猜配 |

日级阅读分钟优先复用已有 `experienceEntries`。需要时仅增补可选的轮次关联、来源身份和“单次/书目日总计”范围；不为日历和热力表各建一份活动存储。全局首页是汇总视图，不是第五种媒体。

来源的个人书评修订先显示差异：保留本地感想及另一平台评价，不用一个 `review` 字符串互相覆盖。不把平台公众评分、他人评论或划线点评直接当作整本书的个人读后感。

## 复用与旧数据

- `src/domain/types.ts` 的 `ExperienceEntry` 已有身份、月/日日期、种类与可选分钟。保留原有日期校验；未知/年份阅读史放在可缺日期的轮次，不放宽旧日志来硬塞。
- `CompletionEvent` 是游戏明确完成事实，支持未知/年/月/日及独立录入时间。`catalog.timelineEntries()` 只汇集普通日志，日历需要只读适配这两类身份，不能把普通 completed 日志升级为通关或盲目双计。
- 旧 `status` 原样读；旧 finished 无实际日期时只显示历史已读，不制造有日期轮次。旧 `impression/review` 保留为历史感想，不猜轮次、来源或评分换算。
- 启动、浏览、取消、同值操作不补写。只有明确编辑或确认导入才沿用 repository、修订冲突、原子保存与备份链写入。

## 每日分钟、来源与去重

1. 只对明确到日且分钟已记录的阅读计热度；0 无正热度，缺省不是零。有阅读事实但无分钟仍在日清单显示。
2. 相同稳定记录 ID 重导不追加；同书同日的两次独立阅读可相加。不能用“书＋日期”作为单次身份。
3. 手工记录与来源可能重叠时，预览中关联同一事实或明确确认为独立；日总计与其明细二选一入账，未解决不相加。
4. 累计时长、进度、最后阅读时间不能还原日级轨迹。来源没有稳定日级身份时，不承诺自动幂等。
5. 来源提供日历日期时按其原精度保留；时间戳需要确认时区后归日。跨午夜有起止证据才拆；只有某日 30 分钟就保持某日 30 分钟。
6. 微信读书统计文档存在日级候选，但可能是账号阅读/收听总计而非每书明细；不能把账号日总计分配给若干书，或直接与栖域手工分钟相加。第一期建议先支持明确的手工日级记录，来源接入独立验收，详见 [来源契约](../research/BOOK_SOURCES.md)。

## 生命周期、兼容与回退（建议）

- 删活动不删书；取消计划不删历史。历史隐藏作品保留事实，回收作品建议默认从日历和热力表排除，恢复后重现；永久删除的记录归属和来源排除需一起确认。
- 完整 `.roost` 备份应保存所有关联及回收作品，JSON 兼容能力按字段矩阵验证。不能只靠 schemaVersion 相同断言旧版可写。
- 新旧版本不交替编辑同一数据目录。升级前保留旧版可读原文，新版另存完整备份；回退使用旧副本，新版记录单独留存，禁止默认降级写回。
- `MetadataProvider` 的扩展涉及 `types.ts`、`library.ts` 校验、`catalog.ts` 来源匹配、`importExclusions.ts`、候选 DTO、IPC、批量导入与备份，不是只加一个字符串。

## 需要所有者确认的三项

1. 接受“版本书目＋计划＋阅读轮次＋独立个人评价”的最小关系，旧字段只读回退，不进行启动迁移。
2. 接受共用日志记录日级分钟、疑似重叠先预览、先提供手工记录；账号聚合时长在未验证归属前不混入。
3. 接受回收作品默认排除统计及新旧版分副本回退；具体白名单和完整备份验证通过后再正式落字段。
